# Gregal Jocs HTTP API contract

Routes that only exist with the games registered. Everything else is Gregal's server: see `../gregal/docs/api-contract.md`.

## Gregal Jocs (games)

These routes exist only in the Gregal Jocs binary (`jocs/cmd/gregal-jocs`),
which is the same server plus the games (`jocs/server`, registered through
`web.RegisterProduct`). The Gregal binary has none of them: `/api/arena*` and
`/api/football*` answer 404 `{"error":"not found"}` there, and `/jocs/` is a
short page saying the games are a separate app. Both plugins (`games`,
`arena`) follow `/api/plugins` like the Corner.

Gregal Jocs has its own profile and shares nothing with Gregal: config,
keys, accounts and tokens in `~/.config/gregal-jocs`, data (sessions,
service descriptor `service-jocs.json`, league state) in
`~/.local/share/gregal-jocs` (`GREGAL_DATA_DIR`, `GREGAL_AUTH`,
`GREGAL_MEMORY` and `--config` still override). Every route of the shared
server above answers from that profile.

| Route | Method | Response |
|---|---|---|
| `/api/jocs/model-import` | GET/POST | "Use the same model as Gregal", once. GET → `{offer, state, provider?, model?, label?}`: `offer` is true only for the administrator, when Gregal Jocs has no model that can answer (the provider of the active role has no key and is not local), the import was neither done nor dismissed (`state` "" / `imported` / `dismissed`, stored in `<config dir>/gregal-model-import.json`) and Gregal's profile has a working one (`~/.config/gregal/config.yaml`, the model picked in Gregal's UI from `~/.local/share/gregal/model-preferences`, the key from its `config.yaml`, a `${VAR}` with a value, or its `auth.yaml`); `label` is the catalogue name. POST (admin; 403 otherwise) `{action:"import"}` → `{ok, provider, model}` copies that provider, model and key into Gregal Jocs (every role, like the onboarding preset; a literal key goes to Gregal Jocs' `auth.yaml`, a `${VAR}` is copied as a reference); 409 if it was already imported, Gregal Jocs already has a working model or Gregal has none. `{action:"dismiss"}` → `{ok}` stops the offer. Gregal's files are only read; it is a one-time copy, never a live link. Not a plugin: always on. |
| `/api/football` | GET/POST | The winds' American football league. GET → `{teams:[{id,name,abbr,color,color2,coach,record,players:[{id,name,pos,number,color,style,wind,attrs}]}], games:[{id,status,started,score,teams}], today, max_per_day}`. The league is created on first use from the league's members (`<user state>/football/members.json`, `{version:1, members:[{id,name,role,specialty,color,style,persona}]}`: coaches, stars and the commentator; a default set of three is created when there is none), completed with team players; `wind` on a player marks a member (its id). It never reads or writes Gregal's winds, «Avui» or wind news. POST `{action:"play"}` → `{id}` starts a game (409 if one is running or 3 were played today); `{action:"reset"}` builds a new league (the members stay). |
| `/api/football/match` | GET/POST | GET `?id=&after=N` → the game with the plays numbered above `N` (`{status: pregame|live|final|stopped|failed, teams, plans:[{q,team,coach,note}], plays:[{n,q,clock,off,down,dist,spot,kind,detail,dir,depth,yards,end,complete,int,fumble,td,safety,good,first,turnover,penalty,actors,score,hl,text,comment,drive}], score, quarter, summary, mvp, commentator, stats}`; with `after>0` the rosters are omitted). POST `?id=` `{action:"stop"}` stops it. The viewer page `/app/football-viewer.html#id=<id>&token=<key>&lang=ca` draws it on its own (the phone uses it in a WebView). |
| `/api/arena` | GET/POST | The Arena (prompt competition). GET → `{me, display, admin, games:[{id,title,starter,rules,playbook:{sections:[{id,title,intro,rule,unit?,mine:[{id,label,plain}],theirs:[…],grid:[[-2..2]],values?:[[n]]}]}}], next:{game:{owner,display,level}}, seeding:[game], progress:{game:[{id,started,kind,opponent,result,score,coach}]}, mine:{game:{md,display,updated,versions,history:[{at,hash,size,current?}]}}, bots:{game:[{owner,display,level,md}]}, leaderboard:{game:[{owner,display,elo,played,won,lost,drawn,bot}]}, competitions, matches, practice_left, slots:{official,practice}, event:{name,tagline,date,place}, totals:{matches,official,players,decisions}}`. For administrators it also has `planner:{entries:{game:n}, bots:{game:n}, match_secs}` (strategies saved per game, bots, and the average length of the last finished matches, 480 when none) so the organizer page can estimate how long a competition takes. `event` is the competition as the Gregal Jocs site shows it (defaults: "Gregal Prompt Cup" and its tagline; `date` unix, 0 = none); `totals` counts every match on the server (`players` = distinct non-bot owners, `decisions` = model calls). `matches` are headers only (no events, decisions, md, feedback, lines, analysis or preview; `queue` while waiting), served from an in-memory cache keyed by file mtime + size. `history` lists the `.md` versions, oldest first, the current one last (`hash` = first 8 hex of its SHA-256, `size` in bytes). POST `{action}`: `version` (`game, at` → `{at, md, current?}`: that version's text; 404 if none), `event` (admin; `event:{name, tagline, date, place}` → the saved event; name ≤60, tagline ≤140, place ≤80 characters; stored in the arena `settings.json`), `slots` (admin; `official, practice` → `{official, practice}`: matches played at once, 1-8 each, default 1 and 2; stored in the arena `settings.json`; a running competition starts up to `official` matches at once, group games in parallel and each playoff series game after game), `save` (`game, md, display`; max 12000 chars, keeps 20 versions), `practice` (`game, md?, display?, opponent?` → `{id}`: saves `md` first (the template if there is none yet); without `opponent`, the easiest bot not yet beaten; 6 a day per player), `review` (`game, md?` → coach feedback), `seed_bots` (admin; `games?`: the model writes the bots' `.md`). Users are the server's accounts (`local` without accounts). `playbook` is the editor's «what beats what» guide, generated from the engine's matchup tables: `grid[i][j]` is how my option `mine[i]` does against their `theirs[j]` (+2 clear win … -2 clear loss), `values` the engine number behind it (CS2: % of rounds the row side wins, `unit`), and `rule` the `.md` line template with `{mine}`/`{theirs}`. Team mode: GET also returns `teams` (the organiser's list, `[]` = off) and `my_team`, plus `team_members:{owner:team}` for admins; POST `{action:"teams", teams:[name]}` (admin) replaces the list (trimmed, unique, at most 40 of 40 characters; members of a removed team lose it) and POST `{action:"team", team, owner?}` sets my team (`""` = none; another `owner` is admin only; 400 for a team not in the list). |
| `/api/arena/match` | GET/POST | GET `?id=&after=N` → `{id, game, kind, comp, stage, owners, names, titles, status, meta (when after=0), events:[{n,kind,text,hl,score,decision,data}], decisions:[{n,side,short,decision,why,rule,fallback,rule_found}], followed:[share per side of decisions whose rule is really in the .md], model, score, winner, feedback:[{scores,summary,strengths,mistakes,suggestions}], md, analysis:{headline,text,side,rule,audio, moments:[{n,side,rule,what,why,event}]}}`. `analysis.moments` are the prompt moments (up to 6, in match order; `event` is the play that shows it): checked against that side's `.md`, computed by the server for older/demo matches, and hidden for a side whose `.md` is hidden.feedback:[{scores,summary,strengths,mistakes,suggestions}], md}`. Another player's `.md`, rules quoted and report stay hidden until it is an official finished match. `?situation=N&side=S` → `{n,side,situation,schema}`: what the model saw for that decision. POST `?id=` stops it (owners or admin). Matches wait for a slot (official and practice separately, see `slots` above); while `pregame` the match carries `queue: N` (1 = next). Lighter polling: `md` is only sent with `after=0` (or no `after`); `dafter=K` returns only `decisions[K:]` plus `decisions_total`, `lafter=K` only `lines[K:]` plus `lines_total` (no parameters = everything, as before). Each decision also has its cost: `ms` (with retries), `calls`, `pt`/`ct` (prompt/completion tokens), `cached` (prompt tokens served from the provider cache), `memo` (a practice answer reused for a byte-identical prompt). The match has `hints` (the decision format lists each call's counters; on in practice, the competition's setting in official matches) and `stats:{decisions, calls, retries, fallbacks, memo, prompt_tokens, completion_tokens, cached_tokens, model_ms, queue_ms, wall_ms, all_calls, all_prompt_tokens, all_completion_tokens, all_cached_tokens}` (`all_*` include casters, analysis and coach reports; tokens are 0 when the provider does not report usage). Bots get no coach report in practice matches. |
| `/api/arena/competition` | GET/POST | GET `?id=` → `{title, games, status: ready|running|done|stopped, model, schedule:[{game,stage,phase,a,b,match,matches,series,replays,winner,score,done,pending,from}] (playoffs are best of 3: score = series wins), current, champion, names, titles, tables, entries (revealed when done)}`; without `id`, the list. POST (admin) `{action:"create", title, games?, bots?, hints?}` (`hints`, default false: the NFL decision format lists what each call stops and is beaten by; also returned as `hints` by GET) snapshots every player's `.md`, seeds groups by Elo and builds groups + playoffs (a game where no person has a `.md` is left out; 400 when no game has one; bots play the groups (never against each other) but only people qualify for the playoffs, so an empty playoff spot is a walkover and the champion is always a person; groups of 3-5 named A-Z, then a bracket sized to the qualifiers: Final, Semifinal N, Quarterfinal N, "Round of 16 N", "Round of 32 N", group winners first, classic seeding and no same-group pair in the first round); `start`; `stop`. |
| `/api/arena/stream` | GET | `{competition, script}`: the running (or latest) competition, as above, plus the broadcast script `{lang, voice, opening:{text,lines,audio}, explain:{game:{title,lines,audio}}, champions?:{text,audio}}`. Matches add `preview`, `preview_audio`, `lines:[{n,text,audio}]` (caster) and `analysis:{headline,text,side,rule,audio}`. For `/app/arena-stream.html#token=<key>` or `#spectator=<link key>`; add `overlay=scorebug|standings|bracket` for a transparent OBS overlay of just that piece (the bracket and tables are drawn by `app/arena-bracket.js`). |
| `/api/arena/voice` | GET/POST | GET `?k=` → the cached narrator audio (wav/mp3; 404 while it is being made). GET → `{config:{engine: piper|http|off, url, model, voices, extra}, install:{state,step,done,total,error}, ready:{ca,en}, platform, sizes, voices:{lang:[{who,name,label,license,card,mb,installed}]}}` (never the key; a GET also starts downloading the English Piper voices when Piper is installed but they are missing, e.g. after a voice change). POST (admin) `{action}`: `install` (`lang`; downloads Piper and the missing voices, then deletes retired ones), `config` (`config:{engine, url, key, model, voices, extra}`), `test` (`who: caster|analyst, lang, text?` → `{key}`). |
| spectator link | — | `X-Arena-Spectator: <key>` (or `#spectator=` on the stream page) allows only `GET /api/arena/stream`, `/api/arena/match` and `/api/arena/voice?k=`. POST `/api/arena/competition {action:"spectator", reset?}` (admin) returns or renews it. |
| `/api/arena/live` | GET/POST | CS2 played live in `/app/arena-cs2-live.html`: the human plays one player, bots the rest, the model calls each round. POST `{action}`: `start` (`md?, display?, opponent?, format: short|full, slot: 0-4, roles:[5], notes:[5]` → `{id, meta, names, human, team, half}`), `plan` (`id` → `{setup, decisions}`: the model's round call for both teams and the bots' orders; the same round again until its result arrives), `result` (`id, result:{round, human, tracks, kills, utils, plant, defuse, explode, endT, dmg}` → `{score, done, winner, events}`: the server applies the rules), `stop` (`id`), `roles` (`slot, md?` → `{roles, notes}` from the model). GET `?id=` → the state. Saved as a match of kind `live` (not ranked). |
| `/api/arena/starter` | GET | `?game=` → the template `.md` as a download. |
| `/api/arena/season` | GET | The season by person, for the asking user. `{players:[{owner, display, rank, games:{game:{elo, rank, played, won, lost, drawn, history:[[unix, elo]], bots:[level]}}, played, won, lost, drawn, official:[w,l,d], elo, form:["W"|"L"|"D"], streak, best_streak, bots_beaten, followed, principles:{clarity, specificity, coverage, adaptivity, consistency}, reviewed, prompt_score, coach_first, coach_last, moments, last, archetype?, emoji?}], awards:[{id, icon, title, owner, display, value, why, match?}], highlights:[{match, game, kind, stage, side, owner, display, rival, rule, what, why, n, event, impact, clutch?, lead?, won, score, at}]}`. Players are the non-bot owners (matches or a saved `.md`); `rank` orders them by average official Elo (`elo` 0 = no official match), then bots beaten, `prompt_score` (average coach total, 0-100) and wins. `elo`/`history` only move with official matches (replayed like the stored ratings). Numbers (results, coach scores, `followed`, moment counts) are public; a highlight quotes a `.md` line, so it is listed only when that side is visible (own, bot, or an official finished match), at most 2 per match and 40 in all, highest `impact` first. `awards` (`leader`, `architect`, `by_the_book`, `giant_killer`, `on_fire`, `most_improved`, `playmaker`) are computed, the same for everyone, and absent without enough data (3 matches). Also: `players[].vs_bots:{rookie|solid|expert:{played, won}}`, `players[].team`, `players[].games[g].versions:[{n, at, lines, played, won, coach}]` (each distinct `.md` text that played, up to the latest 12; `coach` 0-100), `quality:{vs_vague:{played, won}, people:{played, won}, rungs:[{owner, name, level, overall:{played, won}, vs_vague:{played, won}}]}` (structured prompts against Bot Rookie, from finished matches, no model call) and `teams:[{name, rank, members, active, xp, prompt_score, improvement, vs_vague, official_wins, bots_beaten, top}]` (only when the organiser listed teams; ranked by average XP). |
| `/api/arena/logo` | GET | The company logo the organiser uploaded for the site header: `{logo}`, a `data:image/(png|jpeg|webp|svg+xml);base64,…` URL, or `""` when there is none. It lives on the server (`<arena>/logo.txt`), never in the code; GET `/api/arena` only carries `event.logo_hash` (first 12 hex of its SHA-256), so the site fetches the image once per change. Set with POST `/api/arena` `{action:"logo", logo}` (admin; `""` removes it; at most 200 KB as a data URL, PNG, JPEG, WebP or SVG; 400 with `{error}` otherwise; returns the event). |
| `/api/arena/report` | GET | Organiser only (admin; 403 otherwise). The learning report as CSV (`text/csv`, attachment `prompt-cup-report-<date>.csv`), one row per person: `player, account, team, xp, matches, won, lost, drawn, coach_reviews, prompt_score, first_coach, latest_coach, coach_gain, clarity, specificity, coverage, adaptivity, consistency, vs_vague_won, vs_vague_played, bots_beaten, official_won, official_lost, md_versions, first_version_win_rate, latest_version_win_rate, last_active`. Coach scores are 0-100; `xp` uses the Prompt level formula (10 per coach-reviewed match, 20 per bot beaten, 30 per official win, 2 per point of the average coach score); the version columns are from the game with most `.md` versions. Cells that a spreadsheet would run as a formula are prefixed with `'`. |
| `/api/arena/player` | GET/POST | GET `?owner=` (default: me) → `{player (as in season), highlights (up to 8 of theirs), matches:[{id, game, kind, stage, rival, result, score, at}] (official ones, plus practice when it is you), insight, insight_stale}`. `insight` is the AI scouting report `{archetype, emoji, tagline, summary, signature, strength, weakness, tip, principle, rival, at, hash, matches}` or null, one per player (`<arena>/insights/<owner>.json`), seen by everyone, so the model only reads public data (season numbers, official moments and the latest official `.md`). `insight_stale` is true when the data behind it changed. POST `{action:"insight", owner}` writes it (one model call; returns the saved one unchanged when the data did not change; 409 with no finished match, 502 if the model fails). 404 for bots and unknown players. |
